# 面向老师与评委的论文汇报思路

## 先确定页数，再提交文案供确认

开始先问用户希望生成多少页 PPT；会话中已给出页数就沿用，不重复提问。总数默认包含封面、结尾和备份页，除非用户明确另算。用户回答后仔细阅读论文，按该页数编写结构和逐页文案；保留用户要求的内容语言。

向用户呈现每页的编号、用途、标题、核心结论、实际屏幕文案、拟用图表/公式及原文出处。讲稿如有需要单独列出，不能只给目录标题就请求确认。询问是否需要修改或可按此稿制作；按反馈修订，用户明确确认文案后才开始 PPT 制作。仅给出页数、没有回复或超时都不算确认。若用户已明确接受当前文案并要求继续，直接承接该版本，不重走确认流程。

在 `content-plan.json` 中记录确认状态和对应文案版本，制作时以该版本核对；尚未确认时不能把计划标成已确认。排版调整不需要重复确认，改变核心主张、页数或内容范围则需先让用户确认修改。

## 读论文时先建立论证表

按“作者的主张”阅读，不按 PDF 页码直接切片。核对摘要、引言、方法、实验、附录中同一主张是否有不同条件。提取：任务的输入/输出与约束；已知做法及其具体不足；作者的洞见；实际新内容；验证设计；最强支持证据；未覆盖情形。

为每项贡献填一行：

|贡献主张|为何需要|方法对应|支持证据|适用条件/局限|报告位置|
|---|---|---|---|---|---|
|来自目标论文的主张|原方法的具体失效|模块/目标/算法步骤|原文图表/定理及页码|数据、假设、对照条件|预告→方法→实验→结尾|

“使用 Transformer/扩散模型”本身未必是贡献。区分已有组件、作者改动和实验性发现。没有证据支持的强主张应收窄，不用听起来更强的措辞掩盖。

文献汇报讲“作者提出”“论文在某条件下报告”；自己的复现、解释和批评单独标注。原论文没测试的限制写成“尚未验证/值得讨论”，不能装成已观察失败。若有原始代码或更新版本，区分论文结果与后续实现，不静默混用。

## 将论证转换为可制作的页面计划

在 `content-plan.json` 中记录总页数、报告类型（作者报告/文献汇报）、受众、选定变体，以及每页的 `id`、`role`（主讲/备份）、`question`、`claim`、精确文案、`source_refs`（论文页码/图表/公式）、`evidence_assets`、`layout_pattern`、`reference_ids`、`expected_objects`。字段可按工具适配，但不要丢失结论与来源的对应。原文没有支持的结论先修改计划，不在制作时补造。

相邻页之间补一句转场：上一页留下了什么问题，下一页将如何回答。讲稿补充“为什么”，屏幕保留图、关键式和短要点，避免把完整口语稿塞进幻灯片。定量结论可按“在什么条件下，哪个指标，相对什么对照，发生什么变化”写；定性结论只描述实际可见现象。

## 首页与前两页

**首页**写真实题目，必要时给便于理解的中文副题；论文作者及经核实的会议/期刊、年份；另列汇报人、单位、日期（用户提供时）。长作者列表可合理简写并注明等，不编导师、机构、职称或会议信息。论文作者和汇报人不能混为一组。用该变体的封面版式，避免无关科技城市背景。

**尽早给贡献预告**：一句任务/难点、核心洞见、两三项真正贡献，以及一个最有代表性的结果预览。G02、F02、P02分别提供结构、摘要、能力演示三种做法。预告给听众地图，后续仍需逐项证明，不是提前宣布无条件胜利。

若任务陌生，可先用一个输入→目标输出案例解释，再讲贡献。目录是可选的；短报告不要为行政目录占据珍贵页数。

## 中间如何展开

1. **具体问题与缺口。** 用失败例、任务定义、条件对比或简洁示意指出“哪里没解决”；背景只保留理解此缺口所需内容。相关工作比较围绕关键差别展开，引用到位。
2. **核心洞见。** 把问题转换成可操作设计：为什么这种表示、目标或约束可能解决失效？它依赖什么假设？视觉论文可沿用同一案例，理论论文可用贯穿的简单数学例子。
3. **方法总览。** 说明输入、输出、主要模块、数据/控制流；区分训练和推理，区分已知组件和新增部分。之后的局部页能回到同一总图的位置。
4. **关键机制。** 不必解释所有层。围绕贡献讲：为什么有此组件，它改变了什么变量/信息/目标，如何实现，拿掉会发生什么（只讲论文验证过的结果）。公式先给语义、再给核心式、再解释符号与作用。
5. **证据链。** 主结果回答是否有效；消融回答哪一部分有效；定性/误差分析回答在哪些现象上有效；代价与失败案例回答使用边界。并非每篇论文都有每类证据，缺失就明确说明，不制造占位实验。

三种可选叙事路线：

- **模块贡献型（G）**：预告 → 总图 → 按信息流拆组件 → 数据/偏差 → 多组基准 → 机制可视化。
- **问题修正型（F）**：失败现象 → 设计要求 → 初始机制 → 剩余缺陷 → 新机制 → 定量与定性验证。
- **能力与控制型（P）**：能力演示 → 表示与变量 → 操作如何改变变量 → 训练/推理 → 分能力比较 → 控制消融。

视觉主题与叙事路线不必一一绑定；可以用极简白底讲机制修正，但标题、字体和边距应保持统一。

## 实验页如何让评委判断

读者要知道：什么数据与划分、测什么、数值越大还是越小、与谁比、是否同条件，以及结论有多大范围。

- 保留单位、↑/↓、数据集、设置、样本数或误差条（原文提供时）；表格选择与当前结论有关的列，删列需说明筛选范围。
- 压缩率、输入分辨率、数据规模、训练资源、预训练、推理预算不同，应显式标注；把不同条件的最高数字并排不等于公平提升。
- 同一行比较同一输入、提示词、裁剪与缩放；原图/基线/本方法/GT 标签准确。局部放大应指明对应区域，不挑换不利样本冒充同例对比。
- 用加粗、细框、局部放大引导到证据。高亮按真实排名；某列没赢就保留。不得“全部SOTA”概括部分胜出。
- 消融说清固定项、改变项和观测；定性例子支撑现象，不自动得到统计结论。注意力热图不是因果实验。
- 没有可获取原数据时保留原图，或仅忠实转录可核验数值；不能为了可编辑曲线凭视觉猜出采样点。

## 结尾与备份

主讲结尾应能回答“我们应记住什么”：一句核心洞见；一到两条带条件的主要证据；一个真实局限/未解问题；必要时给讨论问题。文献汇报可增加“我的判断”，与作者原结论分开。自己研究可写下一步，但应从当前证据缺口推导，不自动套项目计划。

Thanks、Q/A、论文/代码链接和二维码可选，使用已核实地址；二维码应由已核实地址编码并验证实际可扫。详细推导、完整表格、额外样例、相关工作可作备份，目录标明主讲与备份。用户限定总页数时，备份也计入，除非另有要求。

## 不同长度的页序示例

以下是压缩/展开方式，不是固定模板。用户的时间、论文类型和页数优先。

|总页数|可行结构（数字为页数）|
|---:|---|
|6|封面兼问题1；任务/洞见与贡献1；方法总览1；关键机制1；核心结果兼消融1；结论/局限/讨论1|
|10–12|封面1；预告1；问题/相关差距1；方法总览1；关键机制2–3；实验设置与主结果2；消融/讨论1；结尾1；如有剩余再分配备份|
|15–20|在10–12页基础上展开关键机制、不同证据与失败分析；留适量备份，避免重复五页同质表格|

6页不等于每页堆满：优先删次要贡献、旁支机制和重复结果。若实在无法同时清楚展示方法与证据，在总页数内选择主论点并交代省略范围。

迁移到其他学科时保留论证关系：理论报告以假设—定理—证明直觉—反例/边界支撑；系统报告以瓶颈—设计—负载/资源条件—性能与代价支撑；NLP报告以任务、数据与评测协议、误差/偏差支撑。不要硬塞图像编辑示例或不存在的实验。
