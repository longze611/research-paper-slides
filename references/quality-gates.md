# 质量门槛与交付

## 逐页与全套检查

**论证完整性**：前两页是否让听众理解问题与贡献？每个主贡献是否连接到具体方法与证据？方法是否先有全貌再有局部？实验是否真正测试了对应主张？结尾是否回扣问题、结果和局限？若某项证据原文没有，是否诚实标注而非补造？

**事实忠实**：题目/作者/年份、图表出处、公式符号、指标方向与单位、实验设置、基线标签和真实排名逐一核对。区分作者结论、汇报者解释与未验证推测。不能为了版式删掉影响结论的条件。

**视觉一致**：同时打开所选原始参考页与最终 PPT 渲染页，按下列维度比较，写出实际偏差与修正，不以“学术风”三个字通过：

|维度|核对|
|---|---|
|页面骨架|同一变体的白底/近白、标题位置/色带、页码和边距|
|字体层级|标题/小标题/正文/注释的字号和字重有区别；中文覆盖、混排基线、局部强调和分点缩进正确，主文不能全退化为浅灰细字|
|空间分配|主视觉明确；复杂图标签在演示尺寸可读；简短模块无大块空底色；双栏主次、对齐线和栏间距合理|
|封面与结尾|封面题目与身份层级清晰，避免色块/段落/复杂图同时堆叠；结尾有主次，不以多组同权重文字占满四角|
|图示造型|细边线、克制圆角、模块体积随内容调整；端口/箭头统一，条件标签靠近分支，避免不必要斜线和嵌套卡片|
|关系表达|总图到模块、连续修正、同例比较的组织是否对应|
|色彩语义|模块/变量一致，保留科研证据图例，强调克制|
|信息密度|可投影阅读，避免模仿原稿过小公式或P06低对比|
|证据呈现|可读数字、准确列头、表格组间分隔与数字对齐、可追溯图注，局部标记不误导|
|页脚与密度|图注靠近对应证据，来源/页码位置稳定；缩略图看重心，演示尺寸看正文和图内标签，不以放大后可读替代投影检查|

**文案落实**：将用户确认的逐页文案与最终页面核对，检查文案语言是否符合用户选择，以及标题、结论、页序、总页数、图表/公式与证据条件。必要的排版缩写不得改变含义或删掉影响结论的限制。

**可编辑与运行**：正文为原生文本；表格/方法节点等按计划原生化；原生图表含真实可编辑数据；完整 PPT 可正常打开、渲染；代表对象实际编辑成功。位图证据和降级项有说明。不能把图片 PPT 称作可编辑版本。

## 必须完成的渲染—检查—修复—复检

1. **渲染最终导出文件的全部页面。** 保存 `renders/S01.png...`，先看全套联系表检查风格、重心与页序，再逐页以演示尺寸查看。复杂流程图、表格、公式和密集图注还需局部放大；不能只看缩略图或只检查样张。
2. **检查重叠、越界与裁切。** 检查文字/文字、文字/图片、图片/图片的意外相交，包括标题与正文、图注与图表、节点标签与边线、表格文字、页脚与来源。检查文字溢出、异常换行、行距过紧、对象超出画布、图片裁切丢失图例或公式残留字符。结合实际可见内容判断，不能仅凭逻辑边界框认定安全。图内必要标记和有意叠加可保留，但必须清晰且不遮挡证据。
3. **检查组件位置与连线语义。** 根据论文关系及元素映射逐条核对：源节点与目标节点正确；箭头方向正确；端点接到指定节点的对应连接侧/边界；无悬空、错接、意外穿入节点或被遮住的箭头头部。分支、汇合、反馈、训练/推理关系正确，条件标签靠近对应分支，线路避免穿过文字或无关对象。不能凭 `head` / `tail` 字段名或连接器对象存在就认定关系正确。
4. **修改源文件并重新导出。** 对非预期重叠、文字溢出、组件错位和错误连接，调整位置/尺寸/换行/间距、图片裁切或连线路由。移动节点后同步更新所有关联连接器及标签，不能只修箭头外观而改变科学关系。
5. **复查修复结果与连带影响。** 重新渲染受影响页，重复检查重叠、裁切、组件和端点；全局字体/模板或批量布局变更后重新检查全部受影响页面。最终预览、PPTX 与源文件必须对应同一修复版本。存在未解决的非预期重叠或错误连接时继续修复，不进入正常交付；工具受阻无法完成渲染时，明确标记验收未完成。

在 `qa-report.json` 或等效记录中按页记录检查范围、具体问题、涉及对象/连接关系、修复措施与复检结果；无问题页也记为已检查。静态碰撞/越界检测可辅助定位，但不能替代逐页目视与科学语义核对，也不能证明没有字形重叠或连线错误。

## 可选静态检查计划

脚本使用Pillow检查PNG，使用标准库检查PPTX结构；执行环境缺Pillow时使用可用的文档运行时。`content-plan.json`可包含更多事实与布局字段；脚本读取以下字段：

```json
{
  "slide_count": 2,
  "slides": [
    {"id": "S01", "expected_objects": {"text": 2}},
    {"id": "S02", "expected_objects": {"text": 3, "diagram_nodes": 4}}
  ]
}
```

这是格式示例，实际页数与对象下限来自当前计划，不照抄示例数量。`expected_objects`支持 `text`、`table`、`chart`、`diagram_nodes`、`formula`，值为非负整数，表示该类原生对象最低数；`diagram_nodes`通过形状名 `diagram-*`统计，`formula`只统计原生OMML。所有页应有有效原生文字。

从技能根目录运行：

```bash
python scripts/audit_outputs.py --renders <PPT渲染目录> --pptx <最终PPTX> --plan <content-plan.json> --report <audit.json>
```

脚本检查16:9、S01起连续命名的PNG、页数、ZIP完整性、非空原生文本、计划对象下限、图表嵌入工作簿；大面积图片会产生人工检查警告。结果为 `passed_static_checks` 仅表示静态通过，不证明没有重叠、箭头连接正确、图像可见、内容正确、视觉一致或实际编辑成功。分组坐标、矢量图中的文字、公式降级等需另行检查；解决警告或记录其合理原因。

## 交付清单

完整流程通常交付：

- `report.pptx`：可编辑报告；说明保留位图的科学素材/降级部分。
- `renders/S01.png...`：最终 PPT 逐页渲染图片，与交付文件一致。
- 联系表或PDF预览：方便快速浏览。
- 已确认内容计划、事实来源、样式锁定、元素映射、可复现制作源及素材、逐页检查与修复记录：可合并为源文件 ZIP。
- 简短检查结论：实际检查范围、重叠/连接问题修复及复检结果、可编辑范围和已知限制。

最终回复以可下载文件与核心内容为主，不夸大“完全可编辑”或未经验证的检查结果。用户只要求技能创建或更新时，仅修改技能与相关资源，不据此自动新建整套报告。
